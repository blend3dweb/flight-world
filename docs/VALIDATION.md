# Проверки и контрольные снимки

## Правила сравнения

- Один адаптер, браузер, размер окна, качество, положение камеры, время симуляции и заданная погода для «до/после».
- Основной профиль: NVIDIA RTX 5050 Laptop, Chrome, 1920×1080, высокое качество. Записывать фактически выбранный адаптер, а не только запрошенный `powerPreference`.
- Снимки существующей серии: 1600×900; узкий экран: 390×844. Новые контрольные ракурсы добавлять к общей серии, не заменяя её без отметки.
- Проверять движение в живом приложении: статичный кадр не выявляет мерцание, скачки LOD, поворот облаков или рывки отражения.
- Во время замера не запускать вторую 3D-сцену или другую GPU-нагрузку. Отмечать ограничения питания, режим ноутбука и дополнительные нагрузки, если они известны.
- Не перезаписывать `stages/01-baseline` … `07-final` и отчёты закрытых этапов.

## Контрольные состояния после каждого этапа

| Группа | Состояния |
| --- | --- |
| Город | День, закат, ночь, фасады вблизи, крыши сверху |
| Вода | Бухта у поверхности днём и ночью; дополнительно открытая вода и берег на низком пролёте |
| Погода | Солнце, дождь и снег в одинаковом ракурсе; переход между режимами |
| Растительность | Лес с высоты, ближний лес, трава у земли, переход уровня детализации |
| Самолёт | Кабина с появившимся HUD, внешний вид спереди и сбоку, автоматический облёт в полёте |
| Инфраструктура | Аэропорт, дорога/входы, мост и причалы |
| Интерфейс | Узкое окно, переключение качества, пауза, ручное управление и возврат на автопилот |

Для проверки HUD дать пройти времени его появления. Кадр сразу после `reset()` специально содержит начальное состояние с ещё невидимыми приборами.

## Автоматические проверки

- [ ] WebGPU действительно активен; нет ошибок JavaScript, валидации GPU, потери устройства и зависшего экрана загрузки.
- [ ] Работают пауза, управление, смена камеры, облёт, сброс и выбор места старта.
- [ ] Смена суток проходит через полночь; дождь и снег включаются и выключаются, автоматическая погода меняется.
- [ ] Облака сохраняют положение при повороте камеры на фиксированном времени.
- [ ] GPU-маска ночных окон стабильна; количество светящихся пикселей близко к половине исходного на том же адаптере.
- [ ] Отражение содержит текущий город: сравнить сохранённые изображения с видимой и скрытой городской группой в области воды.
- [ ] Здания и входы соответствуют кварталам; нет пересечений с дорогами и неверной высоты оснований.
- [ ] Деревья отсутствуют на зарезервированных участках; мелкие детали отключаются на расстоянии, ближние пулы не переполняются.
- [ ] Крыши используют отдельные материалы, ВПП и мост согласованы с рельефом.
- [ ] После прогрева смена погоды и длительный полёт не вызывают неограниченного роста ресурсов.

## Команды

Выполнять из корня проекта при запущенном `node serve.cjs`.

```powershell
$env:FLIGHT_GPU='nvidia'
node stage-review.cjs 08-ocean-check
node gpu-audit.cjs 08-ocean-check
node gpu-city-audit.cjs 08-ocean-check
node gpu-ocean-audit.cjs 08-ocean-check
node gpu-vegetation-audit.cjs 09-vegetation-check
node gpu-atmosphere-audit.cjs 11-atmosphere-check
node gpu-performance-audit.cjs 12-performance-check
node gpu-reflection-turn-audit.cjs 13-reflection-check
node gpu-benchmark.cjs 08-ocean-check
```

Проверки Agent Bridge выполняются без сохранения кадров и видео:

```powershell
node agent-bridge-audit.cjs
node agent-controller-audit.cjs
node agent-active-observer-audit.cjs
node agent-resilience-audit.cjs
node ollama-dispatcher-audit.cjs
node ollama-defect-sensitivity-audit.cjs
```

Имя папки менять на новый текущий этап или новую проверку. Скрипты принимают имя этапа. `stage-review.cjs` создаёт папку и галерею снимков.

`gpu-benchmark.cjs` требует имя новой папки результата. Завершённые этапы 01–07 и папки с `complete.json` защищены от перезаписи. Для повторной проверки использовать новое имя, например `13-reflection-check-02`. Генератор `stage-gallery.cjs` содержит завершённые этапы 01–13 и сравнение текущей сцены с предыдущим завершённым этапом.

`stage-contact.py <имя-этапа>` создаёт обзор снимков и копирует текущие исходники WebGPU в `source`. Выполнять только когда исходники соответствуют именно этому этапу; для старой галереи нельзя копировать новый код задним числом.

Тестовые скрипты используют Playwright из Codex runtime. На другом компьютере установить Playwright и заменить абсолютный путь в `require` на локальную зависимость. Для обзорных изображений нужны Python и Pillow.

## Производительность

Сохранённая контрольная серия `07-final/benchmark.json`: видимый Chrome, 1920×1080, высокое качество, NVIDIA; средний FPS по сценариям приблизительно 56.2 / 53.6 / 62.7 / 71.8. Это прежний замер, не новое измерение после переноса и не гарантия постоянного FPS.

Для каждого нового этапа:

1. Выполнить прогрев. Измерить город днём, ночной облёт, низкий полёт в дождь и аэропорт в снег.
2. Сохранить средний FPS, медиану, p95/p99 времени кадра, разрешение, качество и адаптер. Выполнить три одинаковые пробы каждого сценария и использовать медиану; сырые пробы оставить в отчёте.
3. Сравнить с предыдущим этапом на тех же настройках. При ухудшении среднего FPS или p95 более чем на 10% определить причину и оптимизировать либо явно документировать компромисс качества.
4. Ориентир основного режима — около 60 FPS; не объявлять его достигнутым по одному короткому замеру. Проверить также «Сбалансированное» качество.
5. Выполнить не менее 150 секунд живого полёта с полным циклом суток и всеми режимами погоды; сравнить ресурсы после прогрева и в конце.

Данные `renderer.info.memory` отражают учтённые движком ресурсы, а не всю видеопамять процесса. Диагностика кадров без окна и замер живого приложения в видимом браузере должны оставаться раздельными.

## Артефакты готового этапа

- `report.json` — функциональные проверки и параметры сцены.
- `gpu-audit.json` — окна, облака, отражения и ресурсы.
- `geometry-audit.json` — геометрия и инфраструктура.
- `ocean-audit/report.json` — стабильность остановленной воды, движение волн, реакция на ветер и переход границы сетки.
- `vegetation-audit/report.json` — статистика экземпляров, стабильность паузы, движение от ветра, LOD, посадка травы и зарезервированные зоны.
- `atmosphere-audit.json` — мировое положение облаков, сутки, погода, туман, экспозиция, мокрые поверхности и геометрия осадков.
- `performance-audit.json` — частота планарного отражения, разделение кубической карты и PMREM, расписание теней и остановка отрисовки на паузе.
- `reflection-turn-audit.json` — покадровая частота отражения при вращении кабины, восстановление обычного интервала и сравнительная нагрузка поворота.
- `benchmark.json` — производительность и длительный прогон.
- PNG контрольных состояний, `contact.jpg`, галерея и сравнение «до/после».
- `source/` — соответствующий контрольный снимок исходников без дублирования `node_modules`.
- Краткая запись о визуальной оценке: что исправлено, какие дефекты остались, какие ракурсы просмотрены.

Видео в этот набор не входит. Его создавать только после проверки сцены и отдельной команды пользователя.
