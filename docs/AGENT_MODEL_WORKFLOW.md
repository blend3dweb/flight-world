# Нейромодель и контроль разработки

Принятое рабочее решение:

- `qwen3.5:4b` выполняет роль глаз и диспетчера;
- Codex контролирует процесс, данные, исходный код и результаты проверок;
- `qwen3.5:9b` остаётся выключенным резервом для отдельных сложных случаев.

Настройки находятся в [agent-model-config.json](../agent-model-config.json), а обязательный формат результата 4B — в [agent-defect.schema.json](../agent-defect.schema.json).

## Поток данных

```text
WebGPU-сцена
  → Agent Bridge: RGB + depth + normal + object ID + телеметрия
  → qwen3.5:4b: визуальное описание и список возможных дефектов
  → структурированный JSON
  → Codex: проверка доказательств и связь с исходным кодом
  → изменение кода и автоматические тесты
  → Agent Controller: возврат в ту же точку
  → qwen3.5:4b + Codex: проверка результата
```

## Обязанности 4B

Модель наблюдает сцену, находит возможные отклонения, указывает координату, object ID, семантическую категорию и предполагаемый модуль. Она оценивает уверенность и выбирает одно решение:

- `pass` — заметных отклонений нет;
- `reinspect` — нужен другой ракурс или дополнительный сенсор;
- `dispatch-to-codex` — есть проверяемый дефект с доказательствами.

4B не редактирует файлы, не выполняет Git-команды и не публикует сборку.

## Обязанности Codex

Codex проверяет каждый вывод модели по объектным данным, телеметрии и исходному коду. Неподтверждённые предположения отклоняются или отправляются на повторный осмотр. Подтверждённая проблема превращается в изменение кода с проверкой сборки и повторным маршрутом.

Решение о качестве строится не только на ответе 4B. Требуется совпадение нескольких источников:

- визуальное наблюдение;
- object ID или raycast;
- связанный модуль кода;
- телеметрия либо воспроизводимое состояние;
- повторная проверка после исправления.

## Использование 9B

`qwen3.5:9b` не загружается автоматически. Его можно вручную вызвать, если 4B несколько раз возвращает низкую уверенность или не различает сложную визуальную причину. Перед запуском 9B модель 4B должна быть выгружена из Ollama. Codex всё равно проверяет итоговый вывод 9B.

## Хранение данных

Сырые изображения не сохраняются в постоянную память. Сохраняются структурированные находки, координаты, object ID, модуль, сенсорные метрики, решение модели и результат проверки Codex. Это позволяет воспроизводить ход разработки без накопления кадров и видео.

## Реализованная интеграция

`ollama-vision-dispatcher.cjs` отправляет RGB-кадр в локальный Ollama API вместе с телеметрией, статистикой depth/normal/object-ID проходов, центральным raycast и ограниченным каталогом видимых объектов. Ответ формируется по `agent-defect.schema.json`, после чего локальный валидатор:

- отклоняет неизвестные поля и неверные типы;
- удаляет выдуманный object ID, которого нет в текущем наблюдении;
- выравнивает semantic и module по известному объекту;
- не разрешает автоматическую диспетчеризацию уверенной находки без object ID или модуля;
- всегда помечает результат как требующий проверки Codex.

Полный эталонный маршрут из шести состояний пройден моделью `qwen3.5:4b`. После уточнения инструкции все нормальные эффекты дождя, снега, ночи, отражений и заката были правильно оставлены вне массива дефектов. Для воспроизводимости установлены `temperature: 0` и `seed: 42`. В последнем горячем проходе шесть ответов заняли в среднем 3,01 секунды, последние пять — 2,96 секунды. Отдельный чистый проход ранее показал 10,26 секунды на первый ответ с загрузкой модели. Сырые кадры в отчёт и постоянную память не попали.

Эталонный маршрут подтверждает отсутствие ложных срабатываний на нормальных состояниях. Полнота обнаружения проверяется отдельным обратимым дефектом ниже.

## Проверка чувствительности

Контрольный дефект создаётся только во время аудита: все объекты сцены временно скрываются, RGB-кадр проверяется в памяти, затем видимость каждого объекта восстанавливается. Исходники сцены не меняются, изображения на диск не записываются.

`qwen3.5:4b` не обнаружила даже пустую сцену и вернула `pass`. Поэтому её результат нельзя использовать как самостоятельное разрешение продолжить автоматический цикл. Контроллер сравнил сенсорные метрики с эталоном, обнаружил изменение средней яркости на 56,99 и стандартного отклонения яркости на 32,83 и принудительно заменил решение на `reinspect`. После восстановления сцены итог снова стал `pass`.

Резервная `qwen3.5:9b` была запущена отдельно после выгрузки 4B, но Ollama завершила `llama-server` при инициализации CUDA рядом с WebGPU-сценой. На этом ноутбуке 9B остаётся выключенной.

Текущая граница ответственности:

- 4B формирует описание и предварительное решение;
- контроллер проверяет RGB-метрики и запрещает доверять `pass` при значительном расхождении;
- Codex проверяет каждую находку и решает, нужен ли другой ракурс, другая модель или изменение кода;
- автоматическое исправление кода пока не разрешено.
