# Нейромодель и контроль разработки

Принятое рабочее решение:

- `qwen2.5vl:3b` выполняет роль глаз и диспетчера;
- Codex контролирует процесс, данные, исходный код и результаты проверок;
- `qwen3.5:9b` остаётся выключенным резервом для отдельных сложных случаев.

Настройки находятся в [agent-model-config.json](../agent-model-config.json), а обязательный формат результата — в [agent-defect.schema.json](../agent-defect.schema.json).

## Поток данных

```text
WebGPU-сцена
  → Agent Bridge: RGB + depth + normal + object ID + телеметрия
  → qwen2.5vl:3b: прямое описание видимых пикселей
  → детерминированное решение и структурированный JSON
  → Codex: проверка доказательств и связь с исходным кодом
  → изменение кода и автоматические тесты
  → Agent Controller: возврат в ту же точку
  → qwen2.5vl:3b + Codex: проверка результата
```

## Обязанности локальной vision-модели

Модель наблюдает сцену, описывает видимые категории и отмечает возможные отклонения. Координату, object ID, семантическую категорию и модуль добавляет контроллер по сенсорным данным, а Codex проверяет эту связь. Итоговое структурированное решение принимает одно из значений:

- `pass` — заметных отклонений нет;
- `reinspect` — нужен другой ракурс или дополнительный сенсор;
- `dispatch-to-codex` — есть проверяемый дефект с доказательствами.

Vision-модель не редактирует файлы, не выполняет Git-команды и не публикует сборку.

При `reinspect` Agent Controller автоматически ставит промежуточную точку между плановыми азимутами и немного поднимает наблюдателя. Число дополнительных попыток ограничено, поэтому неоднозначный объект не создаёт бесконечный цикл.

## Обязанности Codex

Codex проверяет каждый вывод модели по объектным данным, телеметрии и исходному коду. Неподтверждённые предположения отклоняются или отправляются на повторный осмотр. Подтверждённая проблема превращается в изменение кода с проверкой сборки и повторным маршрутом.

Agent Controller хранит этот процесс как конечный автомат. Vision-модель может только создать находку. Решение об исправлении принимает Codex с явным перечнем файлов. Контроллер запоминает их исходные SHA-256, принимает запись об исправлении только после реального изменения одобренного файла, перезагружает сцену и воспроизводит исходный осмотр. Самостоятельная запись исходников контроллером запрещена.

Решение о качестве строится не только на ответе vision-модели. Требуется совпадение нескольких источников:

- визуальное наблюдение;
- object ID или raycast;
- связанный модуль кода;
- телеметрия либо воспроизводимое состояние;
- повторная проверка после исправления.

## Использование 9B

`qwen3.5:9b` не загружается автоматически. Его можно вручную вызвать, если основная модель несколько раз возвращает низкую уверенность или не различает сложную визуальную причину. Перед запуском 9B основная модель должна быть выгружена из Ollama. Codex всё равно проверяет итоговый вывод 9B.

## Хранение данных

Сырые изображения не сохраняются в постоянную память. Сохраняются структурированные находки, координаты, object ID, модуль, сенсорные метрики, решение модели и результат проверки Codex. Это позволяет воспроизводить ход разработки без накопления кадров и видео.

## Реализованная интеграция

`ollama-vision-dispatcher.cjs` отправляет RGB-кадр в локальный Ollama API. `qwen2.5vl:3b` сначала описывает только видимые пиксели и проверяет обязательные категории текущей точки. Контроллер детерминированно преобразует этот ответ в `agent-defect.schema.json`, добавляет телеметрию, статистику depth/normal/object-ID проходов и центральный raycast, после чего локальный валидатор:

- отклоняет неизвестные поля и неверные типы;
- удаляет выдуманный object ID, которого нет в текущем наблюдении;
- выравнивает semantic и module по известному объекту;
- не разрешает автоматическую диспетчеризацию уверенной находки без object ID или модуля;
- всегда помечает результат как требующий проверки Codex.

Полный эталонный маршрут из шести состояний пройден моделью `qwen2.5vl:3b`: город днём и ночью, мост под дождём, аэропорт, острова со снегом и океан на закате получили `pass`. Для воспроизводимости установлены `temperature: 0` и `seed: 42`. После добавления активного наблюдателя контрольный проход занял в среднем 1,74 секунды на состояние, пять горячих ответов — 1,87 секунды; ранее на том же маршруте получено 0,81 секунды. Сырые кадры в отчёт и постоянную память не попали.

Эталонный маршрут подтверждает отсутствие ложных срабатываний на нормальных состояниях. Полнота обнаружения проверяется отдельным обратимым дефектом ниже.

## Проверка чувствительности

Контрольный дефект создаётся только во время аудита: все объекты сцены временно скрываются, RGB-кадр проверяется в памяти, затем видимость каждого объекта восстанавливается. Исходники сцены не меняются, изображения на диск не записываются.

`qwen2.5vl:3b` сама обнаружила пустую сцену: сообщила об отсутствии города, зданий, дорог и рельефа и назначила `reinspect`. Сенсорный барьер независимо подтвердил значительное расхождение: средняя яркость изменилась на 56,99, стандартное отклонение — на 32,83. После восстановления сцены vision-модель снова вернула `pass`.

В первом реальном цикле разработки Qwen сообщила, что аэропорт отсутствует в нескольких ракурсах. Проверка Codex выявила две связанные причины: фраза об отсутствующем ожидаемом объекте ошибочно преобразовывалась в `pass`, а имя родительской группы `city, airport and harbour` переклассифицировало дочерние объекты города как аэропорт. Диспетчер теперь проверяет отрицание именно ожидаемых категорий, Agent Bridge классифицирует собственное имя объекта раньше имени предка, а корень WebGPU-города имеет явную семантику `city`. Повторный облёт аэропорта завершился тремя `pass`; отчёт сохранён в [verification/agent-real-development-cycle.json](verification/agent-real-development-cycle.json).

В первом автономном задании ночного аэропорта модель не смогла различить полосу в темноте. После исправления ориентации RGB, локального освещения и масштаба обзора повторный ночной обход завершился `pass` с двумя дополнительными ракурсами. Формулировки неопределённости и прямое отрицание наличия аэропорта ведут к `reinspect`; [отчёт ночного обхода](verification/agent-night-airport-cycle.json) хранит только структуру наблюдений. Дневная растительность и мост под дождём также прошли на живой сцене; [отчёт заданий](verification/agent-mission-audit.json) хранит только структуру наблюдений.

Следующее живое задание связало управление самолётом с наблюдениями: «город → мост → аэропорт». За 31 управляемый шаг самолёт достиг обеих целевых точек маршрута, а `qwen2.5vl:3b` вернула `pass` для города, моста и аэропорта. Отдельный тест проверил остановку, продолжение и восстановление страницы с детерминированной подставной моделью; [живой результат](verification/agent-flight-mission-live.json) и [результат проверки управления](verification/agent-flight-mission-audit.json) явно разделены.

Строгое требование сразу сформировать большой JSON снижало визуальную чувствительность малой модели. Поэтому рабочий конвейер разделён: сначала свободное визуальное описание, затем детерминированное преобразование в схему и проверка сенсорами. Это сохраняет прямое свидетельство модели в `perception` и не позволяет генерации структуры скрыть видимый дефект.

Резервная `qwen3.5:9b` была запущена отдельно после выгрузки прежней 4B, но Ollama завершила `llama-server` при инициализации CUDA рядом с WebGPU-сценой. На этом ноутбуке 9B остаётся выключенной.

Текущая граница ответственности:

- `qwen2.5vl:3b` формирует описание видимых пикселей и предварительное решение;
- контроллер проверяет RGB-метрики и запрещает доверять `pass` при значительном расхождении;
- Codex проверяет каждую находку и решает, нужен ли другой ракурс, другая модель или изменение кода;
- автоматическое исправление кода пока не разрешено.
- управляемый цикл проверки, фиксации изменения и повторного осмотра реализован; изменение исходников выполняет Codex вне Agent Controller.
