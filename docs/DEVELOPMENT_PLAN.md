## 14. Agent Bridge — присутствие нейромодели внутри виртуального мира

Статус: начат, работает первый прототип 0.1.0. Назначение этапа — дать нейромодели возможность непосредственно наблюдать работающую WebGPU-сцену, перемещаться в ней, исследовать дефекты и проверять внесённые изменения без экспорта видео и обязательного сохранения рендеров в файлы. Текущий протокол: [AGENT_BRIDGE_PROTOCOL.md](AGENT_BRIDGE_PROTOCOL.md).

### Архитектурный принцип

Agent Bridge связывает живую симуляцию и нейромодель двусторонним локальным каналом. Сцена передаёт визуальные и структурированные наблюдения прямо из текущего состояния приложения, а агент возвращает ограниченный набор команд управления. Видеофайл для этого контура не создаётся. Визуальный сигнал читается из framebuffer в памяти только с нужной частотой и разрешением.

Контур работы:

`сцена → наблюдение → анализ нейромоделью → действие → новое состояние сцены → повторная проверка`.

### Границы первого прототипа

- Agent Bridge работает только локально и не публикует управляющий интерфейс во внешний интернет.
- Первый прототип управляет наблюдателем и состояниями сцены, но не изменяет исходный код без отдельного рабочего цикла разработки.
- Непрерывное изображение не требуется: агент получает кадр по событию, при движении или для подтверждения результата.
- Пользовательские камеры, управление самолётом и обычный режим демонстрации продолжают работать независимо от агента.

### Готовность

- [ ] Агент самостоятельно входит в сцену, выбирает маршрут и осматривает заданный объект с нескольких сторон.
- [x] Агент одновременно получает визуальное наблюдение, глубину, нормали, идентификатор объекта и телеметрию соответствующего состояния; центральный ID автоматически сверяется с raycast.
- [ ] Агент способен найти объект по семантическому запросу, приблизиться к нему и определить связанный материал или модуль сцены.
- [ ] После изменения параметра агент воспроизводит исходные условия и подтверждает результат повторным наблюдением.
- [ ] Работа Agent Bridge не требует записи видео и не создаёт заметных задержек в обычном полёте при отключённом режиме инспекции.
- [ ] Протокол, ограничения, тесты и результаты прототипа документированы отдельно до перехода к автономному изменению кода.

## Закрытие каждого этапа

1. Зафиксировать конкретные дефекты и исходные снимки.
2. Внести изменения в одну систему, затем проверить связанные системы.
3. Выполнить [автоматические проверки и контрольные состояния](VALIDATION.md).
4. Просмотреть PNG; для движения выполнить живой прогон без записи видео.
5. Сравнить FPS, время кадра и ресурсы на том же устройстве и настройках.
6. Исправить найденные регрессии и повторить затронутые проверки.
7. Сохранить исходники, отчёты, снимки, ограничения и статус этапа; обновить галерею и этот чеклист.

Тест, наличие снимка и визуальная оценка — отдельные пункты. Успешная сборка не означает, что изображение достигло нужного качества.
